Data Model (Firebase RTDB)

RTDB ek bada JSON tree hota hai — koi joins nahi hote, is liye data jaan-boojh kar duplicate kiya jata hai taake reading fast rahe.

/users/{uid} username, bio, avatarUrl, createdAt /usernames/{username} : uid → fast username lookup + prefix search ke liye /posts/{postId} uid, imageUrl, caption, createdAt, likeCount /userPosts/{uid}/{postId} : true → "is user ke posts" nikalne ke liye /feedPosts/{postId} : { uid, createdAt } → MVP feed = sab logon ke posts, newest pehle /follows/{uid}/following/{otherUid} : true /follows/{uid}/followers/{otherUid} : true /notifications/{uid}/{notifId} type (like | comment | follow), fromUid, postId, read, createdAt

Search ke liye RTDB mein full-text search nahi hota — /usernames pe orderByKey().startAt(q).endAt(q+"") se prefix search karte hain.

Feature 1

Users (Authentication)

Login aur Sign up — app ka entry point. Har user ka ek unique username hota hai jo Search aur Profile dono mein use hota hai.

Login Sign up

App Launch — Pehla Screen Kaun Sa Khulta Hai?

Yeh sabse pehla decision hai, Login screen dikhane se bhi pehle:

  1. App open hoti hai
  2. App check karta hai: FirebaseAuth.getInstance().currentUser — kya session already saved hai?
  3. Session maujood hai → Login screen skip, seedha Home Feed
  4. Session nahi hai → Login screen dikhta hai
Firebase Auth SDK session ko khud secure storage mein save karta hai — app ko manually token check karne ki zarurat nahi, bas currentUser null hai ya nahi dekhna hota hai.

Signup — Agar Account Nahi Hai (Step by Step)

  1. "Don't have an account? Sign up" tap karta hai
  2. Form fill karta hai: Email, Full name, Username, Password (6+ chars)
  3. Username type karte waqt debounced availability check chal sakta hai (optional, acha UX)
  4. "Sign up" button dabata hai
  5. Client-side validation pehle — email format, username characters, password length — fail ho to network call hi nahi jata
  6. App GET /usernames/{username} check karta hai — taken hai to error, yahin ruk jata hai
  7. App FirebaseAuth.createUserWithEmailAndPassword() call karta hai
  8. Success → naya uid milta hai
  9. RTDB mein do writes: /users/{uid} aur /usernames/{username}
  10. Home Feed pe navigate

Advanced edge case (abhi sirf note) Username check aur account create ke beech koi doosra user wohi username le sakta hai (race condition) — RTDB mein SQL jaisi transaction safety nahi. MVP ke liye accept kiya gaya risk hai.

Login — Jab Account Already Maujood Hai (Step by Step)

  1. Email + password darj karta hai, "Log in" dabata hai
  2. Client-side sanity check (khali fields na hon)
  3. App FirebaseAuth.signInWithEmailAndPassword() call karta hai
  4. Firebase email + password server pe verify karta hai
  5. Success → uid milta hai, session device pe save ho jata hai
  6. App /users/{uid} se profile read karta hai
  7. Home Feed pe navigate

Feature 2

Profile

User ka apna profile — avatar, bio, stats, aur uske posts ka grid.

Profile Load — Step by Step

  1. Bottom nav se "Profile" tab tap karta hai
  2. App current uid nikalta hai, loading skeleton dikhata hai
  3. Parallel mein teen reads: /users/{uid}, /userPosts/{uid}, /follows/{uid}/...
  4. /users/{uid} aate hi header render — avatar, naam, bio
  5. /follows aate hi stats row update — .getChildrenCount() se
  6. Har postId ke liye alag /posts/{postId} read (N+1 pattern, MVP ke liye theek)
  7. Grid mein thumbnails fill hoti jati hain
  8. Koi posts nahi → empty state: "Abhi tak koi post nahi"
Real-time listener zaroori nahi yahan — screen open hone par ek baar fetch kaafi hai. Follower count har second change nahi hoti.

Edit Profile — Step by Step

  1. "Edit profile" tap (sirf apne profile pe dikhta hai)
  2. Form khulta hai, current values pehle se bhare hue
  3. Avatar badalta hai to → same Photo Picker → Worker → R2 flow jo Create Post mein hai
  4. Bio/naam sirf text hai, koi upload nahi
  5. "Save" tap → client-side validate (e.g. bio max length)
  6. UPDATE /users/{uid} — sirf changed fields, poora object overwrite nahi
  7. Success → form band, updated data turant dikhao
  8. Fail → error dikhao, form band mat karo, unsaved changes rakho
Edit Profile fail hone ki wajahUser ko kya dikhao

Bio bohat lambi"Bio 150 characters se zyada nahi ho sakti" (client-side hi roko)
RTDB write fail"Changes save nahi ho sake — dobara try karo"

  3. "Edit profile" button gayab, uski jagah "Follow"/"Following" button
  4. App check karta hai: /follows/{myUid}/following/{otherUid} exist karta hai? → button state decide hota hai
